# Board Card Editing and Imported Commissions

The authenticated `/board-entries` routes share the same access rules in the
board preview and full proposal/issue pages. Content editing and commission
configuration are independent operations.

| Endpoint | Purpose |
| --- | --- |
| `GET /board-entries/:kind/:id` | Content, edit permissions, attachments and authorized commission context |
| `PUT /board-entries/:kind/:id/content` | Versioned title/Markdown save; `kind` is `proposal` or `issue` |
| `POST /board-entries/:kind/:id/images` | One validated image in multipart field `file` |
| `PUT /board-entries/:kind/:id/commission` | Create or update an imported art agreement |
| `GET /board-entries/clients?q=…` | Creator-only account lookup; exact email matching, no email in output |
| `GET /board-entries/images/:id/:token` | Image delivery using a 256-bit bearer capability |

Content versions hash the title and body. External content is read before
editing and checked again before writing. An identical external result is
accepted on retry after a lost response. Trello writes hold the existing board
sync claim and advance its local/remote content snapshots without changing
placement. Attachment retries first inspect the remote attachment list. A
partial attachment failure reports text success separately.
Editor uploads send multipart image bytes to Trello, not a URL-only attachment.
The remote description uses the uploaded file URL; Orbiters maps it to the loaded
local image capability when reading and back to the native attachment when writing.
Retries match confirmed uploads before posting. Only matching old Orbiters link
attachments are removed, after the uploaded file is confirmed.

GitHub writes use `GITHUB_REPOSITORY_WRITE`, scoped to the configured repository,
not an identity token. Orbiters uses the official
[issue update endpoint](https://docs.github.com/en/rest/issues/issues#update-an-issue).
Trello uses its [card and attachment endpoints](https://developer.atlassian.com/cloud/trello/rest/api-group-cards/).
Notion tasks use the same editor API with a workspace-owned provider, remote version
checks and advanced-block preservation; see [Notion board integration](16-notion-boards.md).
Configure `PUBLIC_API_URL` with the externally reachable API origin so both
providers can display inline images. Image capabilities are stored hashed in
file metadata; the original link is retained on the authorized card attachment.
Deleting the owning card invalidates delivery. Uploaded images are private
storage objects, never a public bucket redirect.

Each linked asset uses its own `ArtCommissionRequest`. Its first client remains the
primary `clientId`; `snapshot.clientIds` records all selected participants.
Participant queries cover request lists, homepage summaries, references,
payments, private proposal/issue access and self-service export. The existing
payment record holds the agreed amount and receipt date independently of the
configured quote. No provider payment or new customer terms acceptance is
generated by importing an existing agreement.

`snapshot.boardEntry` identifies the source and `snapshot.selection` retains
the listing choices. `boardCommissionLinks` resolves the requests pointing to a
proposal or its linked GitHub issues, alongside a native website order reference.
The editor returns `commissions[]` and a card-wide `commissionVersion`. Saves use
`requestId: null` to add an asset or the exact linked request ID to edit one, plus
the card version and that request's payment version. Source-row locks and version
checks prevent duplicate imports; duplicate assets are rejected. Existing native
requests cannot be replaced by this editor. Each agreement is filtered by its
participants before returning clients, options or payment data. Shared brief edits
update every linked agreement belonging to the creator.
All of this uses existing JSON fields and request/payment models; no schema
migration is required.

Slider options store minimum/maximum integer prices and 1–100 intervals. A
selection stores a bounded integer step; the backend derives its price using
integer-cent rounding. Freeform extras have a nonempty name and nonnegative
price, with at most 20 extras per request. Both paths use the same quote rules.

The browser loads the rich-text editor on demand. A dropped image gets a local
preview node; its identifier follows edits during upload, then its source is
replaced with the permanent URL. Saving is disabled until uploads finish.
Markdown tables and task lists have explicit editor extensions.

Focused backend tests use model, storage and provider fixtures. The browser
tests also cover client validation, separate asset agreements and a Notion callback
without the Creator tab query. `boardCommissionDatabase.test.js` checks actual
PostgreSQL JSON queries for proposal and GitHub issue bindings in an explicitly
isolated disposable database; it is opt-in through `BOARD_LINK_DATABASE_TEST=true`.
The browser
script `frontend/scripts/test-board-card-ui.cjs` exercises a fresh frontend
build in headless Chromium, intercepting every API/vendor request. Set
`PLAYWRIGHT_MODULE` to an installed Playwright module when it is not locally
available. Screenshots and intermediate animation measurements go to
`diagnostics`.
